# UI/UX 與生成圖片多模型審核

日期：2026-09-24。結論：**適合加入圖片，建議先做 1 張首頁主視覺＋3 張學習情境插畫；同時優先修正手機操作問題。** 圖片可強化網站的運動感與模組辨識，實際教學成效仍待測試。

本次只有分析與證據檔，未改產品、案例、提交或部署，也尚未生成圖片。正式站 `https://antidopingplatform.sportsmedicine.tw` 實測版本 `7fcd848d06908b29d37a77b891650f80d6b9877e`，builtAt `2026-09-24T04:54:53.339Z`。現有未提交修改保留。

## 範圍與方法

- 主持人取得正式站 8 路由的 1280×900、390×900 截圖與 DOM；另測首頁及案例頁 320×900，共18組初始畫面，無 pageerror、這18組無水平溢出。
- 補充實際操作：390×844 搜尋→案例→返回、手機選單、篩選開關、藥檢下一步；另測320×844藥檢頁，發現12px水平溢出。不能把最初18組通過外推為全站所有窄螢幕都通過。
- 主持人查看首頁、案例、統計、藥檢等截圖；模型只收到同一份固定 DOM／程式碼證據，**不是四個視覺模型直接看圖審核**。
- 使用者追加 injury 參考後，重新擷取其1280／390首頁，四席再獨立評估同一補充框題；沒有提供其他模型答案。
- 無真實用戶研究、流量、螢幕閱讀器完整測試或效能基準。本輪未重新查核醫療／反禁藥規則，不構成內容背書。

## injury 參考：借用什麼

[參考正式站](https://injury.sportsmedicine.tw/)的桌面首頁為左側標題、統計與CTA，右側多運動群像主視覺。手機保留主視覺但縮小、淡化，文字和按鈕仍可閱讀。主視覺與下方真實影片縮圖各有不同功能。

主持人實際看圖：深色底、青藍重點色、帶寫實質感的運動群像與動態光影。這是視覺觀察，單靠頁面不能證實圖片的生成來源或權利狀態。主圖DOM為`a-all-sport-burst.*.avif`，顯示尺寸桌面781×354、手機302×180，alt空。

反禁藥站可借用**左文右圖的主視覺配置與運動動勢**；保留既有綠色識別，內頁維持淺底易讀。建議風格：深綠／青綠＋米白、帶層次的編輯插畫或半寫實數位插畫；人物明確虛構，避免可辨識名人與隊徽。不必整站改深色，也不必把每張卡變影片縮圖。

## 建議第一批：4張

| 圖片 | 放置與內容 | 生成／排版界線 |
|---|---|---|
| 1. 首頁Clean Sport主視覺 | 跑步、自行車、球類等虛構運動人物群像；桌面右側、左側留白給標題與CTA | 不畫涉案名人、獎牌醜聞、禁藥注射；手機另裁切，不能把CTA推出首屏 |
| 2. 藥檢學習插畫 | 運動員與工作人員說明程序、確認證件或核對文件 | 先畫通知／報到情境，不把生成器械細節當採樣教學標準；精確步驟另以HTML/SVG呈現 |
| 3. TUE學習插畫 | 運動員與醫療人員討論病史及文件 | 不畫核准章，不暗示諮詢即獲TUE；判定邏輯、條件與結果維持互動工具 |
| 4. 測驗學習插畫 | 虛構選手面對用藥／補充品資訊做選擇 | 先放測驗入口，題內是否加圖逐題決定；不靠紅綠瓶子或勾叉洩漏答案，不使用真實品牌 |

首頁三張學習圖使用同一畫風，替換對應卡片的圖示區／做低高度縮圖，不另外堆一層大型Banner；其餘卡片沿用一致圖示及留白。若混合卡片不協調，可把三張插畫集中為「開始學習」三入口，其餘資源另列，而不是立刻補足六張。

案例列表／個案：不生成當事人肖像與歷史現場。首頁「案例搜尋」入口可用抽象資料檢索圖，但不必為517件各生一張。統計：保留真實資料產生的Chart.js與表格。禁用清單：物質名稱、分類、閾值不用生成圖承載。流程箭頭、中文、數字、來源、規則年版皆由HTML/CSS/SVG排版。

### 可交付生圖的共同規格

- 首頁原圖可先以1600×900構圖，左側約45%留白、右側運動主體；另外製作手機裁切，不只把桌面圖縮小。
- 三張模組圖用4:3共通構圖，裁成卡片低高度區域；不內嵌中文字、商標、數字、條碼或官方標章。
- 共通提示方向：「運動教育網站編輯插畫，虛構成年運動員，深綠與青綠、米白輔色，健康自信而不污名化，清楚輪廓與動態光影，無文字、無logo、無可辨識真人，保留介面排版留白」。各張再加入上表情境。
- 人物情境圖鄰近加適當「情境示意」說明；純裝飾圖可空alt，資訊圖則提供對應文字替代。不要把「AI生成」當成圖片可不審核的理由。

## 四模型共識、分歧與主持人裁決

**共識不是事實。** 初輪多數偏保守，Grok反對全部AI圖，GPT允許有限首頁／藥檢示意，Gemini限藥檢器械圖，Claude較支持教學流程圖。四席均反對冒充真人案件、以生成圖取代精確規則或真實數據。

使用者明確提供圖鑑參考後，四席都接受首頁非紀實運動群像。這是**需求補充後的判斷變化，不是初輪四席本來就一致支持**。原答覆與兩輪中立框題均保留。

| 分歧 | 模型立場 | 綜合裁決 |
|---|---|---|
| 第一批張數 | GPT 3張；Grok 4張；Gemini/Claude 7張（hero＋6卡） | 先4張：hero＋藥檢／TUE／測驗。足夠建立風格，範圍可控；不是投票結果 |
| 圖片角色 | 初輪偏重法規精確性；補充輪接受裝飾與教學情境分工 | 採納使用者的視覺目標，不能用「不是必需資訊」否定所有裝飾圖 |
| 卡片是否全配圖 | Gemini/Claude主張全部；GPT/Grok主張部分 | 首批只做3個學習主題；整體卡片高度與構圖需一起設計 |
| 藥檢細節 | Gemini初輪提刻度、雙色A/B瓶；Grok反對生成採樣示意 | 精確器械與程序不用模型想像；先採人員說明／文件情境，流程用可控圖形 |

單席帶來的補充：Gemini凸顯URL狀態問題，主持人已操作重現；Claude指出案例皆使用紅色警告圖示，建議改成能區分類型的文字＋圖示，而不是所有案例視覺上都像違規成立；Grok提醒首頁recentCases區塊未顯示，其原因／必要性未查明，不列已確認缺陷；GPT提醒隨機知識卡不同刷新內容不同，屬設計選擇，不直接列錯誤。

### 未採用／修正的模型說法

- Claude以`overflow:0`推論沒有認知負荷、沒有流失，無證據；並杜撰加圖前LCP為2.0秒，不採用。其10–15人試驗搭配p值門檻也不作統計驗收。
- Gemini將`main img=0`等同「全站零圖檔請求、極致傳輸效能」，範圍過度延伸；這不排除CSS背景或其他資源。本輪未測完整效能。
- 初轮Grok把8路由全三寬度都通過說得太廣；320只初測兩頁，後續藥檢頁確有溢出。
- 「四步驟圖解」有數字、圖示、連接線及切換，不因沒有img就判定承諾不符；可改善情境理解，但不列已證實缺圖缺陷。
- Claude補充輪把12px溢出歸到案例頁，錯誤：是藥檢頁。把y112稱CTA座標也錯：是首頁標題。
- Claude補充輪的lazy loading文字可能導向首圖也延遲載入；修正為首屏LCP圖不lazy，非首屏圖才lazy。
- 不採用未查證的法律斷言、規範百分百保證、零CLS保證、推估的流失率或學習成效。

## 實作驗收建議（尚未執行）

1. 先修搜尋返回及手機搜尋排版、步驟溢出；回饋列收斂後再設計首圖。320／390／1280均重驗。
2. 首頁兩CTA在390×844首屏可見且不受圖片／回饋列遮擋；手機不因加圖使學習入口更難到達。图片失敗仍能理解與操作。
3. 圖片提供AVIF/WebP、srcset/sizes及固定位階尺寸；首圖若為LCP不lazy，卡片非首屏才lazy。建議暫定手機hero≤120KB、桌面≤200KB、單卡≤60KB，為專案預算而非標準，需依視覺實測調整。
4. 裝飾alt空、資訊性插畫有等價文字；對比、鍵盤、縮放及報讀另行驗證。[W3C裝飾圖片指南](https://www.w3.org/WAI/tutorials/images/decorative/)；[web.dev響應式圖片](https://web.dev/learn/design/responsive-images)。
5. 同裝置／網路重複測量加圖前後LCP、CLS與總傳輸量，不能只因AVIF就說更快。[web.dev LCP優化](https://web.dev/articles/optimize-lcp)。
6. 找少量選手／教練／醫療人員做形成性任務測試：找案例後返回、找用藥工具、說出藥檢步驟、辨識圖是情境示意。記錄錯誤與猶豫，不以小樣本宣稱轉換或理解有顯著提升。
